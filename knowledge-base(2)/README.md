# TradeTwin AI 知识库交付包

版本：`0.1.0` · 状态：`synthetic_demo` · 更新时间：2026-10-31

这是一套交给应用/智能体开发队友使用的知识库与测试资料，服务于“客户参数变更后，先算清证据覆盖、最小补测、合规账单和报价选项”的首发场景。原有“出口品质与合规文档自检”保留为底层能力。首发范围限定为**出口欧盟的室内固定式 LED 灯具**。包内业务文件全部是明确标注的**合成演示数据**，不代表真实企业、实验室、客户或证书。

## 先看什么

1. `manifest.json`：确认范围、版本和文件清单。
2. `public-rules/source-index.json`：查看官方公开来源入口；它们是索引和背景依据，不是法律意见。
3. `public-rules/rule-cards.jsonl` 与 `checklist.json`：加载规则卡和机器可读检查项。
4. `synthetic-data/canonical-product.json`：读取唯一产品主数据，再加载三个资料包。
5. `collaboration/`：接入问题卡、负责人和跨部门交接。
6. `test-cases/`：使用标注测试集验证硬伤召回和页码定位。
7. `handoff/`：按接入说明配置检索、输出和第二轮对话行为。

## 核心工作流

1. 读取买家 RFQ 与参数变更，关联当前 SKU、文件版本和报告覆盖范围。
2. 输出 `COVERED`、`NEEDS_RETEST`、`DOCUMENT_UPDATE`、`MANUAL_REVIEW`、`NOT_ENOUGH_EVIDENCE` 状态，并保留页码证据。
3. 推导最小补测候选，生成带假设、来源类型、`synthetic: true` 和人工确认状态的费用/周期估算。
4. 生成方案 A/B 的英语/德语待确认草案；品质/合规、工程、采购/实验室和业务按问题卡接力。

## 首发边界

- 自动检查对象：文件是否存在、关键字段是否可读、型号/功率/电压/版本/样品关联是否跨文件一致。
- 规则资料：CE、低电压、电磁兼容、RoHS、生态设计和 Blue Guide 的官方入口及边界摘要。
- 不自动判断：具体产品的最终法规适用性、认证有效性、清关结果、法律责任和检测机构结论。
- 不覆盖：无线、应急、防爆、电池及没有定义触发条件的产品配置。
- 合成映射不等同于法规强制要求；合成费用和周期不等同于实验室报价。

## 资料性质

`public-rules/` 是公开来源索引与规则卡；`synthetic-data/` 是从统一主数据派生的合成 RFQ、规格书、DoC、测试报告、标签和说明书。每份资料都含“合成演示数据”和页码标记。不要把样例编号、样例公司或样例结论复制到真实业务中。

## 导入顺序与检索键

推荐顺序：`manifest → source-index → rule-cards/checklist → canonical-product → packs → glossary → test-cases`。

常用过滤键：`market`、`product_scope`、`source_id`、`rule_id`、`check_id`、`pack_id`、`document_id`、`owner_role`、`coverage_status`、`test_item`、`option_id`。模型输出硬伤候选或覆盖结论时必须同时返回 `document_id`、正整数 `page`、原文 `quote`、`rule_refs` 和人工边界。

## 风险分类

- `HARD_ISSUE_CANDIDATE`：范围和触发条件成立时发现必需材料疑似缺失或关键事实冲突；需人工确认。
- `RECOMMENDATION`：格式、命名、语言、清晰度等改进建议，不暗示法定强制性。
- `MANUAL_REVIEW`：规则适用性、配置、证据质量或来源关系不确定；不自动判通过/不通过。
- `NO_ISSUE_FOUND_IN_SCOPE`：仅表示已配置检查项未发现问题，不表示认证完成或保证清关。

缺少文件不能自动等同于违法或必然无法清关。任何硬伤候选都要有证据和适用边界；最终决定由品质/合规负责人或企业指定角色作出。

## 五分钟交接演示

1. 载入 `PACK-BASELINE-001`，展示资料一致和范围内未发现问题。
2. 换成 `PACK-CONFLICT-001`，指出 DoC 旧型号、报告样品不一致及页码证据。
3. 展示覆盖分析：24W/IP20/DRV-A 命中，36W/IP44 对功率和 IP 触发补测，DRV-A 沿用仅待确认。
4. 将问题交给品质 → 工程 → 采购/实验室 → 业务，展示方案 A/B 的合成账单和假设。
5. 进行第二轮指令：改用方案 A、只保留硬伤或生成德语追问；系统不能删除源证据或把待核验改为通过。
5. 读取 `test-cases/`，计算 `TP / (TP + FN)` 和页码定位正确数。

## 验收限制

测试集至少 50 条，适合验证资料包内的确定性问题和演示流程；合成结果不能证明生产环境达到 98% 硬伤召回率。正式上线前应使用企业授权、代表性、独立标注的历史资料重新验证，并维护规则版本。

## 结构化校验

在仓库根目录运行：

```powershell
& .\tests\check-knowledge-base.ps1
```

校验脚本检查 JSON/JSONL 的 ID、来源、页码证据、合成标记、资料包和测试集数量。它不执行 OCR，也不调用模型或外部服务。
