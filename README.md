# 贸链通 TradeTwin AI

答应客户之前，先算清合规账单。面向欧盟室内固定式 LED 灯具，把客户配置变更、测试证据、最小补测、费用周期和本地化报价连成一个可回溯流程。

## 本地运行

需要 **Node.js 24+**、npm 和 **Python 3.11+**。所有命令在仓库根目录执行：

```sh
npm ci
python -m venv .venv
# Windows：
.venv\Scripts\python.exe -m pip install -r workflow-1/app/requirements.txt
# macOS / Linux：.venv/bin/python -m pip install -r workflow-1/app/requirements.txt
npm run dev
```

打开 [本机工作台](http://127.0.0.1:5173)。开发命令统一管理 Vite（5173）、Node（3001）和 Python（8000），均默认仅监听本机。优先使用项目 `.venv`；可用 `WORKFLOW1_PYTHON` 指定解释器。首次启动自动建立 SQLite 数据库并载入明确标识的合成示例资料。

生产构建与本机运行：

```sh
npm run build
npm start
```

生产入口为 [本机生产界面](http://127.0.0.1:3001)，Node 提供 API 和打包前端，启动脚本同时管理 Python 工作流。关闭已有开发服务后再运行，避免端口冲突。只调试 Node 时可用 `npm run dev:node` / `npm run start:node`，此时销售功能需要另行启动 Python。

```sh
npm test
npm run typecheck
```

服务已运行时，`npm run test:workflows` 验证 Node → Python → Node 的双工作流真实 HTTP 闭环；`npm run test:smoke` 保留原 Node 接口兼容性检查。默认连接本机 3001，可用 `TRADETWIN_API_URL` 指向其他验收实例。验收会新建独立案件，运行资料保存在忽略目录。

启动前可按需复制 `.env.example` 为根目录 `.env`。没有模型密钥时使用明确标识的本地提取和模板回复，规则引擎照常执行。不要提交密钥、邮箱授权码或运行数据。

## 从案件队列开始

打开应用后默认进入“案件队列”。队列承载多案件查找与比较，单案详情承载实际推演和回复：

1. 在搜索框输入客户、案件、型号或买家原话；空格分隔的关键词按 AND 匹配。按“未推演 / 含人工核验 / 含补测 / 已有回复”组合筛选。
2. 使用更新时间、客户或费用排序；未知费用保持在末尾，不会被当成 €0。可切换每页 10/20 条、列显示和舒适/紧凑密度。
3. 在桌面表格中点击“进入案件”。宽度 ≤1024px 时表格自动转为案件摘要卡片；案件入口、状态、参数变更和费用/交期仍可读。
4. 在“询盘工作台”点击“新建询盘”，选择邮箱或插件入口，输入中文、英语或德语买家原话；创建后直接进入同一案件详情，不再跳到独立销售页面。
5. 若需复现核心演示，打开预置德国客户案件，把请求配置恢复为 **36W / IP44** 后保存并重新推演；不要删除运行数据来制造“干净”状态。
6. 点击“重新推演”查看逐项补测与 EMC 人工复核，生成英语、德语业务回复并查看岗位待办。费用和排期是合成规划值，不是完整报价或交期承诺。
7. 发送“客户选方案 A，30W 和 IP44”，核对温升补测移除、防护补测保留；再发送“暂不承诺具体交期，等实验室排期确认”，核对回复与待办调整。
8. 返回队列后，原搜索和筛选条件会保留；进入证据库导入文档、确认范围，进入知识库搜索或添加资料，进入审计页查看推演、对话和人工覆盖记录。下载案件报告核对完整链路。

品质案件的配置、数量和单价编辑会显示“未保存”。离开未保存配置前会提示，可继续编辑或放弃；刷新或新建询盘时会提示先保存。变更理解、证据核验、补测账单、英德报价和第二轮消息共享同一案件上下文。

## 邮箱与国际站插件

在“新建询盘 → 邮箱”中选择服务商或自定义 IMAP，填写账号和授权码后先测试连接，再保存设置并刷新收件箱。列表可预览会话和邮件正文；只有点击“导入到案件”才会分析所选线程并同步到共享案件。IMAP 对收件仍为只读，不标成已读；往来邮件按回复链归入会话。回复保存到邮箱草稿箱并带回复链头，用户在邮箱检查后自己发送，应用不提供 SMTP 发送。授权码保存在本机工作流服务，更新时留空表示不修改已有授权码。没有邮箱配置时可手动录入；真实邮箱需要自己的应用专用密码或授权码。

Chrome / Edge 在扩展管理页开启开发者模式，加载 `workflow-1/extension/`。插件默认连接本机 Node API：选中文字优先，否则尝试最近一条可识别的买家消息。点击“提交到新建询盘待选列表”前可编辑文本；仅 HTTPS Alibaba 页面可提交，提交前会再次核对来源页面和买家会话。随后在“新建询盘 → 浏览器插件”预览来源、提交时间和原文，再显式点击导入；分析或同步失败时捕获仍可重试。捕获内容只保存在本机 SQLite，10 分钟后过期。回复只填入可信页面编辑器，发送由用户点击；无法识别编辑器时保留复制方式。真实国际站页面尚需登录状态下验收，脚本测试不等于完整站点兼容认证。

架构、契约、方案编号、失败行为与联调步骤见 [双工作流联调](docs/工作流联调.md)。

## 工作台实现边界

- 技术栈为 React 19、TypeScript、Vite、Express、Node.js 24、SQLite、自有 CSS 与 Lucide；本项目没有安装 Tailwind 或 shadcn/ui。
- 案件队列与单案详情共享同一案件记录、规则结果、证据和会话上下文。队列状态、费用和交期来自确定性结果；未知费用会明确显示“待核验”。
- ≤860px 时左侧导航变为带 Menu/X 的滑入抽屉，抽屉独立滚动、`Escape` 关闭并循环焦点；主内容在导航打开时置为 `inert`。
- 主要阅读文字按当前 CSS 为 14px，常用辅助文字为 12px；部分时间、状态和 metadata 仍保留 11px/10px。

## 模型接入

无凭据时可以运行完整的本地演示：参数解析、覆盖判断、费用周期和模板回复真实执行，界面明确标为演示。演示解析器支持常见中英德变更表达，不等同于通用语言模型。

官方 OpenAI 接入可在项目 `.env` 配置 `OPENAI_API_KEY`，并用 `OPENAI_MODEL` 选择账户支持的型号（默认 `gpt-4.1`）。服务端固定调用官方 Responses API（`https://api.openai.com/v1/responses`），不会把官方密钥转发到自定义地址；官方接口参考见 [Responses retrieve](https://developers.openai.com/api/reference/resources/responses/methods/retrieve)。

“知识与规则”中的联网核查使用 Responses API 的 `web_search`，将工具设为必选、按勾选的官方来源传递 `allowed_domains`，并使用 `store: false`。请求发送用户问题、所选来源元数据和检索命中的非合成知识；命中项可能包括手动或 Obsidian 条目。它不自动附带全量报告或本地路径，也不把服务端密钥写入模型上下文。联网回答不会写回规则、费用、交期、报告 `verified` 或案件配置。页面分别显示索引日期与本次实际核查时间，并提供可点击引用。

未配置密钥时按钮显示“查看索引线索”，结果标为“仅本地索引·未联网”，`webSearchPerformed=false` 且 `checkedAt=null`。失败时分别显示“联网未完成·本地回退”或“搜索完成·回答未采用”，不会把本地线索冒充网页回答。

需要其他兼容服务时，复制 `.env.example` 为项目 `.env`，配置兼容 OpenAI Chat Completions 协议的服务：

```dotenv
LLM_BASE_URL=https://your-provider.example/v1
LLM_API_KEY=your-server-side-key
LLM_MODEL=your-model-id
```

该 `LLM_*` 配置只用于非官方的兼容服务；若 `LLM_BASE_URL` 恰为官方地址，适配器仍按固定 Responses API 处理。重启 API，在“接入设置”检查状态和测试连接。密钥只在服务端读取，不写入知识库、数据库导出或浏览器。接口调用失败、超时或结构不合法时保留本地处理路径，并显示回退状态。既有变更理解与报价接口还会发送询盘、当前配置、会话和分析中的证据摘录给所配置模型；测试判断、金额和周期始终由规则计算。

## 知识与文档

- SQLite 保存案件、消息、报告、知识条目和审计，运行目录由 `DATA_DIR` 配置，默认 `./data`，不进入 Git。
- 用户提供的 `knowledge-base(2)` 自动同步 6 条公开来源、16 条规则卡、16 条检查清单和 16 条中英德术语，本轮新增共 54 条 `KnowledgeEntry`（运行库另保留原有 4 条）；索引链接不代表已收录法规全文。9 条内部规则及其 9 条 checklist 明确标为合成并默认隔离；合成 pack、测试集、expected results、handoff prompt 不进入模型默认知识上下文。同步采用稳定 ID、事务 upsert 和同包过期条目清理，手动/Obsidian 条目与相同内容的 `updatedAt` 保留。整合说明与配置见 [知识库与联网核查](docs/知识库与联网核查.md)，包内冲突与隔离记录见 [知识库包核验](docs/知识库包核验.md)。
- 默认运行知识由 `server/runtimeKnowledge.ts` 从知识包 canonical product、真实基准 Markdown 和规则卡校验加载；费用、打样排期与映射政策在 `knowledge/runtime-profile.json`，假设边界在 `knowledge/runtime-profile.md`。`server/seed.ts` 仅保留旧案兼容与历史 fixture。知识源、规则或费用变化会使旧派生结果失效；人工编辑和上传原件保留。
- 支持文本/Markdown/结构化 JSON 及可提取文字的 PDF。扫描 PDF 或无文本资料会显示失败/待核验，需补录或提供可检索版本；本版不冒充完成 OCR。
- 导入的范围是草稿，需要人工确认才能作为已验证证据。报告中的文字不能向服务端授权执行命令。
- 如需 Obsidian，显式配置 `OBSIDIAN_VAULT_PATH=/absolute/path/to/vault`，重启后点击导入；只读处理 Markdown，不自动扫描家目录或修改 vault。
- 原项目 PDF、创新说明与赛事资料保留在 `docs/项目框架/`、`docs/黑客松/`。

## 规则口径

- 36W / IP44：温升 €1,200、6 天；防护 €900、5 天；其他项目按真实范围核对。已知费用小计 €2,100，规划估算 8 天；EMC 待复核时最终报价和确定交期均待确认。
- 30W / IP44：温升在既定覆盖条件内，但原 IP20 不能覆盖 IP44；防护补测 €900、5 天加文档 2 天，为 7 天。
- 配置变更且驱动不变时，EMC 最多给“可能沿用、需人工复核”；不以报告预设验证代替本次变更确认。36W/IP44 换新驱动的演示排期为 `3+max(6,5,7,3)+2=12` 天，已知费用 €3,600；打样 3 天为本次确认的演示假设。
- 证据或关键参数缺失进入人工核验；不可用未知费用伪装零费用。人工覆盖保留原结论及理由。
- 费用、周期、报告、客户和企业案例是合成示意数据。实际适用性与排期须由检测机构和企业专业人员确认。98% 为原框架目标，不是本项目已测得的召回率。

## 项目结构

```text
src/                 React 工作台、证据库、知识与审计界面
shared/types.ts      前后端共享数据契约
server/engine.ts     确定性覆盖/补测/费用周期引擎
server/seed.ts       旧案兼容 fixture 和初始案件模板
server/inquiry.ts    中英德替代方向、选项与意图解析
server/runtimeKnowledge.ts 受控知识源、规则/费用加载与来源指纹
server/db.ts         SQLite 存储
server/model.ts      模型适配与明确标识的演示回复
server/openai.ts     官方 Responses API 服务端调用
server/knowledge.ts  知识索引导入与本地检索
server/research.ts   按索引域名联网核查与引用验证
server/documents.ts  文件解析与知识导入
server/index.ts      HTTP API 与生产静态服务
knowledge/           演示知识源
tests/               规则与 API 验收
docs/                构建要求、方案、演示与验证记录
```

配置、架构、数据来源及交付说明见 [一页方案](docs/方案说明.md)、[模型与数据配置](docs/配置与数据说明.md)、[三分钟演示](docs/演示说明.md)、[实际验证记录](docs/验证记录.md)、[工作台 A 方案验收](docs/工作台A方案验收.md)、[第三方组件](THIRD_PARTY.md)。

运行 `npm run config:export` 可重新生成 [平台配置导出](docs/平台配置导出.json)，其中包含既有 seed 规则、合成覆盖范围、费用和静态知识配置，不包含密钥；运行时知识包的版本、来源和条目计数以 `/api/knowledge/index` 为准，不将该导出文件当作 SQLite 运行时快照。
