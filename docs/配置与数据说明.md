# 配置、模型与数据说明

## 运行配置

| 变量 | 作用 | 默认/说明 |
|---|---|---|
| PORT | API 与生产入口端口 | 3001，本机监听 |
| DATA_DIR | SQLite/运行数据目录 | ./data，Git 忽略 |
| OPENAI_API_KEY | 官方 Responses API 服务端密钥 | 可选；留空为本地演示/索引模式，不进入客户端 |
| OPENAI_MODEL | 官方 Responses API 模型 ID | 默认 `gpt-4.1` |
| LLM_BASE_URL | 非官方 OpenAI 兼容服务根路径 | 包含 /v1；仅非官方地址调用 Chat Completions；恰为官方地址时进入固定 Responses 适配器 |
| LLM_API_KEY | 兼容服务的服务端密钥 | 可选；只在服务端读取 |
| LLM_MODEL | 兼容服务的模型 ID | 与 `LLM_BASE_URL`/`LLM_API_KEY` 一起使用 |
| KNOWLEDGE_PACKAGE_PATH | 知识包固定目录 | 默认 `./knowledge-base(2)`；请求体不能覆盖 |
| KNOWLEDGE_RESEARCH_TIMEOUT_MS | 联网核查超时 | 默认 45000ms，最大 90000ms |
| OBSIDIAN_VAULT_PATH | 显式授权的本地知识目录 | 可选，只读导入 Markdown |

修改配置后重启 API。不要把 `.env`、运行数据库或真实企业报告提交到公开仓库。服务状态接口返回模式、模型名和是否配置，不返回密钥。

## 数据链路与来源

1. 前端提交询盘、配置或第二轮消息。
2. 本地解析器或配置的真实模型产出结构化变更；API 校验字段与类型。
3. 从 SQLite 读取已确认报告与知识。报告保留源文、页码、覆盖范围及人工确认状态。
4. `analyzeChange` 以配置、证据、费用表和规则版本生成内容指纹，确定性输出结论。
5. 英德回复与中文待办只能表达已计算的结果。真实模型负责结构化变更抽取与受限的本地化商务引导语；金额、测试项目、单价摊销、交期条件及中文岗位待办由确定性模板渲染。模型引导语含数字、费用或认证/交期承诺时回退，不能用自由文本覆盖业务事实。失败回退有独立模式标识。
6. 知识核查把问题、所选来源元数据和检索命中的非合成知识发送给官方 Responses API，命中项可能包括手动或 Obsidian 条目。不自动附带全量报告、本地路径或服务端密钥；结果不写回规则、报价、报告确认或案件配置。请求使用必选 `web_search`、域名过滤和 `store=false`。既有变更理解与报价接口则沿用案件上下文，其中可能包含询盘、会话、配置和分析中的证据摘录；这与知识核查请求分开。
7. 案件、会话轮次、生成模式和审计事件保存后返回前端。报告导出保留证据和适用性说明。

运行演示报告由 `server/runtimeKnowledge.ts` 读取 `knowledge-base(2)` 的真实基准 Markdown 和 canonical product，规则关联真实 RULE ID，费用与排期来自 `knowledge/runtime-profile.json`，补充假设见同名 Markdown。它们仍是合成演示资料，不是检测机构原件；预设确认只为演练，不代表真实工程签字。旧 `seed.ts` 报告保留历史/兼容用途。索引检索另导入 54 条（6 个公开来源、16 条规则卡、16 条 checklist、16 条术语），其中 9 条内部规则和 9 条 checklist 标记为合成并默认排除。测试集、expected results 和 handoff prompt 不进入模型默认检索或运行证据。

## 三张核心表

| 表 | 内容 |
|---|---|
| 报告覆盖范围 | 报告编号、项目、系列、功率/IP/驱动/材料/市场、置信度、页码及原文 |
| 参数—测试映射 | 带编号版本的约 15 条初始规则，分别判断范围、依赖与文档/合同变化 |
| 补测费用周期 | 项目成本、准备时长、测试并行与文件串行；示意排期为驱动打样+max(测试)+文件更新 |

同一报告内不同测试可有独立范围。演示的电气强度与温升不应因同在一份安规报告就共享不适用的参数边界。

## 人工与异常

缺少证据、未知参数、缺少费率或未经确认的抽取不得自动放行。文件解析失败保留状态并提示补录。人工覆盖记录原 finding、决定、操作者、理由、时间和规则版本，原推理不被静默删除。Obsidian 路径未配置时提示配置，不自动读取其他目录。

本版是本机单用户原型；没有将演示账号或无鉴权的本机接口宣称为多人生产部署。真实模型服务需使用用户授权的凭据，真实机构数据与规则校准仍需业务负责人提供。

## 官方接口与数据边界

Responses API 固定端点为 `https://api.openai.com/v1/responses`，接口参考为 [Responses retrieve](https://developers.openai.com/api/reference/resources/responses/methods/retrieve)。联网核查只允许来源索引声明的官方 HTTPS 域名（当前为 `eur-lex.europa.eu`、`ec.europa.eu` 及真实子域）；canonical `sourceId` 与同域补充 URL 分开标识。官方返回中 `web_search_call.action`、`query`/`queries`、source `title` 等可选字段按兼容 schema 处理；queries-only 或 bare-source 的合法返回可通过校验，非预期结构或缺少可核验引用则进入本地回退。

有效知识包同步在服务启动时完成：事务 upsert 当前包并清理同包过期 `kbpack-*`，相同内容保留 `updatedAt`，manual/Obsidian 不覆盖。包无效或 stable ID collision 时保留旧库但过滤 active 上下文，避免启动被破坏。

`npm run config:export` 导出受控运行 profile 的主数据、合成报告、规则、费用及来源指纹，不导出用户案件、上传原件、SQLite 全量知识或任何密钥。`/api/bootstrap.runtimeKnowledge` 是当前运行源状态，`/api/knowledge/index` 是公共索引状态；两者用途不同。知识或费用变化使旧推演/报价失效，用户配置、会话、上传原件和人工报告编辑保留。
