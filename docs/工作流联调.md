# 双工作流联调

这次整合保留双方的核心实现：工作流一负责买家变更、候选方案、英德回复；工作流二负责逐项证据覆盖、必要补测、费用和周期。报价中的补测代价来自同一套运行时证据和规则。

## 业务闭环

1. 从邮箱、国际站插件或手工输入取得买家原话，保留出处。
2. 工作流一生成变更单，区分已变更、沿用、暂定与缺失参数。
3. 工作流二按具体测试项目查报告页码、原文、范围和规则，返回可沿用、需补测、文件更新或人工核验。
4. 工作流一把已确认的补测代价与合成商业假设组成多个方案，生成英德草稿与中文岗位待办。
5. 买家选择方案或继续修改时，重新核验和计算；只有措辞变化也保留已选配置。品质侧可打开同一案件查看证据。

## 两个询盘入口

| 入口 | 取得消息 | 回复交付 |
|---|---|---|
| 邮箱 | IMAP 只读选择收件箱，使用 `BODY.PEEK[]`；按回复链优先、参与人和主题辅助聚合同一会话 | IMAP 写入草稿箱，保留 `In-Reply-To` / `References`；用户在邮箱检查后发送 |
| 国际站插件 | 优先读取所选文字，否则识别最近一条可见买家消息；分析前可预览修改 | 只填入可信回复编辑器；发送按钮由用户点击，找不到编辑器时保留复制方式 |

应用不提供 SMTP 发送。邮箱草稿写入不等于发送；插件回填也不等于发送。无邮箱配置时使用明确标识的离线邮件样例。

## 服务与数据

| 组件 | 默认地址 | 责任 |
|---|---|---|
| Node API / 生产界面 | `http://127.0.0.1:3001` | SQLite 案件、证据、规则、知识、审计；工作流二；销售代理和共享同步 |
| Python API | `http://127.0.0.1:8000` | 工作流一编排、提取、候选方案、回复、校验、IMAP |
| Vite 开发界面 | `http://127.0.0.1:5173` | React 工作台；`/api`、`/sales`、`/static` 转发 Node |

生产界面与 API 共用 Node 入口，Python 仍是独立本机子进程。插件默认连接 Node 的 `/api/workflow1`。本次范围为本地工作台，未提供公网多用户认证和部署方案。

工作流一 `session_id` 就是共享案件 ID。Python 保存多轮会话，Node 保存共享配置、当前结果和同步审计。同步以 `run_id` 去重，并拒绝用旧轮次覆盖新轮次。

Node 运行资料默认在 `data/`；Python 会话、邮箱设置和草稿默认在 `workflow-1/app/runtime/`。这些目录和 `.env` 均不提交。邮箱设置中的授权码只在本机服务端使用。

## 工作流二契约

完整字段见 [工作流二接口契约](../workflow-1/app/docs/workflow2-contract.md)。

- 契约版本：`tradetwin.wf2.v1`。
- `GET /api/workflow2/envelope`：产品基线、已确认温升范围、来源页码和证据版本。
- `POST /api/workflow2/evaluate`：接收 `request_id`、适用范围和候选配置，逐配置返回发现、补测、文件更新、费用周期和人工核验状态。
- `request_id` 必须与请求一致；结果配置 ID 不得缺失、重复或增加。
- `rule_version` 标识规则口径；`evidence_version` 由当前证据和费用输入计算。仅改证据、费用或范围也必须改变版本并触发重算。
- 覆盖结论需要报告编号、正整数页码和原文。未知结论或缺失证据不能自动放行。

## 方案与估算口径

方案字母由工作流一分配，A 是买家原要求；是否出现新驱动方案取决于驱动是否已确认；覆盖区间内的替代配置可能是 B 或 C。选择时以当前方案的配置和 `kind` 为准，不套用原主线 A/B 的含义。

| 合成配置 | 补测 | 费用 | 周期影响 |
|---|---|---:|---|
| 36W / IP44 / DRV-A | 温升、防护 | €2,100 | `max(6,5)+2 = 8` 个工作日 |
| 30W / IP44 / DRV-A | 防护 | €900 | `5+2 = 7` 个工作日 |

上述数值要求使用 Node 预置的独立已确认 EMC、材料等证据，并沿用基线材料和德国室内固定灯具场景。30W 仍超出原 IP20 防护范围。驱动不变不能单独证明 EMC 可沿用。

单价由工作流一的合成商业假设叠加补测摊销生成；周期表是补测和文件更新的影响，不是无条件交货承诺。所有费用、周期、报告和企业资料均为合成示例，需专业人员及实验室确认。

## 待核验与故障行为

- 关键参数不全时保留变更单和追问，不假装已确认。
- 未知结论、覆盖无证据、人工核验或工作流二不可用时，不输出确定数值报价；候选配置可以继续讨论。
- 显式离线参考模式缺少独立 EMC / 材料核验，进入待核验属于正确行为，不能把测试专用的已验证夹具当作真实证据。
- Python 不可用时销售页显示可重试错误；案件、证据、知识和审计仍由 Node 提供。
- “暂不承诺具体交期”影响对外回复；内部补测排期仍供业务判断，不把内部估算写成承诺。
- 无模型凭据时使用明确标识的本地提取和规则模板；真实模型、真实邮箱与国际站站点兼容性必须单独验收。

## 演示与验收

按根目录 [README](../README.md) 安装并启动后，在销售工作台输入：

```text
Please change the luminaire to 36W and IP44. Keep DRV-A. 100 pcs.
```

查看变更原文、补测费用和英德草稿；选取“覆盖区间内”30W/IP44 方案，再输入“暂不承诺具体交期”。打开品质核验，确认同一案件、30W/IP44、防护补测保留；返回销售继续同一会话。

自动与浏览器检查的实际执行记录见 [验证记录](验证记录.md)。国际站真实页面和个人邮箱需要有效会话/授权码，模拟测试不能替代这些实际连接检查。
