# TradeTwin AI 一页方案

**目标用户与时刻**：外贸业务收到德国客户的灯具配置变更，需要在回复报价前明确测试证据是否仍适用；品质核验，采购确认物料。

**核心价值**：不是只查 DoC 和规格书字段一致性，而是判断现有证据能否覆盖新配置，生成当前规则下的必要补测集合，并把代价送回报价。

**使用流程**：输入买家变更 → 抽取并确认产品配置 → 按具体项目核验报告范围 → 输出补测/沿用/更新/人工核验 → 计算费用和排期 → 英德邮件/RFQ、中文岗位待办 → 买家第二轮选择方案后重新计算。

**系统架构**：React/TypeScript 工作台调用 Express API。SQLite 保存案件、消息、证据、知识与审计。本地知识库参与证据解释与语言生成。模型适配器使用服务端 OpenAI 兼容接口；无凭据时运行明确标识的演示解析和模板。确定性引擎独立负责覆盖判断、费用与周期。

**两个工作流**：业务端的变更理解与报价选项；品质端的覆盖核验与补测清单。共享案件、配置、报告与规则，不是两段独立的功能演示。

**创新点**：项目级覆盖范围推理；必要补测合并去重和费用周期计算；报价随第二轮配置变化同步更新。证据引用到报告页码、原文与规则版本。

**输入、调用与反馈**：表单或中文/英德变更输入触发 API；提取配置调用规则引擎；结果返回账单和证据批注，语言层输出双语回复和三个岗位待办。异常包括字段缺失、报告未确认、规则不覆盖、模型未配置/失败，均有明确状态和恢复路径。

**两类校验与两类反馈**：证据/目标市场适用性校验、合同交期承诺校验；列表风险标记、证据文本批注与配置对比。

**数据来源与知识库**：本仓库合成报告、产品文档、历史费率及知识 Markdown；活动说明来源于已归档飞书手册和赛题。法规链接仅作来源索引，不能当成产品适用性结论。用户可导入经授权的本地资料，或显式只读导入 Obsidian。没有声称使用任何真实企业生产数据。

**合规声明**：所有演示企业数据、费用与排期为合成示意；参数映射须认证工程师确认；不替代检测、认证、监管或企业合规负责人的判断。凭据仅服务端读取，外部报告文字不授权执行命令。
