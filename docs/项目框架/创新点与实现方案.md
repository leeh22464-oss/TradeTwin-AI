# TradeTwin AI：创新点与实现方案

> 更新日期：2026-10-31  
> 定位：项目框架补充，整理“答应客户之前，先算清合规账单”的三个创新点与最小可行实现路径。  
> 相关材料：[原始项目框架 PDF](<./贸链通 TradeTwin AI｜答应客户之前，先算清合规账单.pdf>) · [AI+出海赛题要求](../黑客松/AI+出海赛题要求.md)

**一句话卖点：业务员答应客户之前，就知道这次改动的合规账单。**

## 一、产品要解决的业务问题

外贸客户经常只改一个参数：功率、防护等级、驱动电源、材料或目标市场。业务员如果先按经验报价，往往在签单后才发现原有检测报告不能覆盖新配置，必须补测、重做文件，交期和利润一起失控。TradeTwin AI 的核心顺序是：**先理解变更，再核验已有证据，推导最小补测，最后把合规代价写进报价**。

它不是把检测机构或认证机构的判断交给模型，而是把报告、页码、参数和规则整理成可回溯的决策材料。示意数据只用于展示流程，最终以检测机构意见、实际报告和费用周期表为准。

## 二、三个创新点

### 1. 证据覆盖范围推理

从“字段是否一致”升级为“现有证据到底覆盖到哪里”。例如 DoC 写 24W、规格书写 36W，只能说明文件不一致，不能直接判断现有报告是否覆盖 36W，也不能直接得出要重做哪些测试。系统先从报告、规格书、DoC、标签和说明书中抽取型号系列、功率区间、防护等级、驱动电源、已测项目、证据页码与原文片段，再与客户新配置逐项比对。

报告的结构化覆盖范围示例：

```text
测试报告 TR-001（示意摘要）
├─ 型号系列：NL-L 系列
├─ 功率区间：18W～30W
├─ 防护等级：IP20
├─ 驱动电源：DRV-A
└─ 已测项目：温升、电气强度、EMC、标签等
```

覆盖条件需要进一步记录到具体测试项目，不能把报告级摘要当作所有项目共同的沿用依据。以下示例均以其他相关条件不变、证据足够且命中已确认的演示规则为前提：

| 客户变更 | 覆盖判断与后续动作 |
|-|-|
| 24W → 28W | 仍在 18～30W 区间内，该区间对应的测试结果可沿用 |
| 24W → 36W | 超出功率区间，温升等相关项目需补测 |
| IP20 → IP44 | 防护等级变化，防尘防水相关项目需补测 |
| 驱动电源不变 | 核验 EMC 项目的独立覆盖条件；匹配时可沿用 |

覆盖判断必须以报告写明的范围和测试条件为准：

```text
客户新配置
├─ 参数与报告范围一致，且条件一致
│  └─ 可沿用：保留报告编号、证据页和适用条件
├─ 参数超出范围，或关键条件发生变化
│  └─ 需补测：生成具体测试项目与理由
├─ 结论仍可用，但配置或市场文件发生变化
│  └─ 需更新：DoC、标签、规格书、德语/英语说明书等
└─ 证据缺失、范围不明或规则未命中
   └─ 待人工核验：禁止自动放行
```

例如，驱动电源不变只是一个有利条件，不能单独推出 EMC 一定可沿用；只有在原报告覆盖范围、测试条件和材料/结构条件都匹配时，系统才给出“可沿用”的示意结论。

### 2. 最小补测方案

系统不把所有测试重新做一遍，而是按参数—测试项目映射找出缺口，输出“必须补测、可以沿用、需要更新”的清单，并同时给出费用、周期和证据来源。这样业务员可以解释每一项成本，也能给客户替代配置。

客户变更示例为 **24W → 36W、IP20 → IP44**：

| 分类 | 项目及依据 |
|-|-|
| 必须补测 | 温升与耐热相关测试、防尘防水测试 |
| 可以沿用 | EMC（驱动等相关条件不变且覆盖匹配）、RoHS（材料不变且证据匹配） |
| 需要更新 | DoC、产品标签、德语说明书 |
| 预估费用 | €X，基于企业历史测试报价表计算；演示使用合成数据 |
| 预估周期 | +10 个工作日，为本说明中的示意值，实际依据排期计算 |

企业价值来自减少不必要的整套重测，同时把真实缺口提前暴露，便于保护报价利润和交付承诺。

方案比较时要保留关键判断：**方案 A 的 30W/IP44 仍然是从原 IP20 发生变化，因此仍需防尘防水测试，不能写成“按原交期”**。A 的交期影响可以低于方案 B，但仍待实验室排期确认；第二轮若重新选择 A，必须重新计算并保留这项补测。说明中的 €X、+10 个工作日也是示意值，不与 PDF 中的 €2,100、+8 天合并为已验证数据。

### 3. 把合规代价写进报价

补测清单不是报告末端的提示，而是报价决策的输入。系统根据规则计算测试费用、文件更新工作量、实验室周期和替代配置，生成中文内部结论以及英语、德语报价选项；客户改变方案后，第二轮可重新推演并同步更新待办。

| 报价选项 | 配置与补测 | 交期与价格表达 |
|-|-|-|
| 方案 A | 调整为 30W/IP44；既定条件下沿用温升结果，仍需补测防尘防水 | 交期影响可低于 B，具体待实验室排期确认；报价计入必要补测费用 |
| 方案 B | 升级为 36W/IP44；补测温升和防尘防水 | 示例延长约 10 个工作日，报价或单价计入新增合规成本，最终排期与价格待确认 |

对外同时生成符合商务语境的德语、英语回复；对内输出中文说明：业务看报价与交期变化，品质看补测和文件更新清单，采购看物料影响及供应商资料待办。

第二轮客户选择 A 后，系统将功率改为 30W 并重新运行规则：移除不再触发的温升补测，保留 IP44 对应的防尘防水补测，同步更新费用、交期、双语报价和各岗位待办。若客户要求暂不承诺具体交期，回复中改为“测试排期确认后告知”，并在内部待办中记录确认责任。

TradeTwin AI 与原方案的差异化定位，是把“变更—证据—代价—报价”连成一条可解释闭环，而不只做 RFQ 回复、文案生成或文件整理。与 Accio 的对比应作为**待核验的定位假设**：Accio 可先作为常规 RFQ、VAT/清关等外贸信息的参照；本项目重点放在检测报告覆盖、最小补测和合规成本前置，不能未经核验断言竞品绝无这些能力。

## 三、三表与模型/规则分工

最小实现采用三张结构化表，把专家确认的规则整理为可执行数据，不要求首版全量理解标准文本；先让规则可复现，再逐步扩展模型能力：

| 表 | 关键字段 | 作用 |
|-|-|-|
| 报告覆盖范围表 | 报告编号、型号/系列、参数范围、已测项目、覆盖条件、证据页码、原文片段、有效性 | 保存“这份报告证明了什么” |
| 参数—测试映射表 | 变更参数、影响测试、规则编号、触发条件、沿用/补测/更新结果、证据页 | 保存“改了什么会影响什么” |
| 补测费用与周期表 | 测试项目、费用、周期、文件更新项、替代配置、数据版本、确认人 | 保存“要花多少钱、多久、如何报价” |

约 15 条初始映射规则覆盖功率超范围、防护等级变化、驱动更换、材料变化、文件更新等主路径。LLM 负责理解客户变更、解析报告、抽取参数与候选证据页码、表达英语/德语结果；确定性规则负责覆盖判断、最小补测推导、费用和周期计算。认证工程师确认参数—测试项目映射，页面/原文回溯保证证据链；命中不了或证据不足时升级人工，不自动放行。示意数据可合成，实际结论以检测机构意见为准。

## 四、业务闭环与最小可行实现路径

```text
买家提出变更
  → LLM 抽取参数、文档与目标市场
  → 证据覆盖模型按报告页码比对
  → 确定性规则生成最小补测/更新清单
  → 费用周期表计算合规代价与替代方案
  → 生成中文决策卡 + 英语/德语报价
  → 业务员确认或人工覆盖并留痕
  → 客户第二轮修改后重新推演、校验、反馈
```

两个工作流应共享同一份产品配置和证据上下文：

1. **变更理解与报价选项**：从询盘、聊天记录或规格书中识别变化，生成方案 A/B 及报价话术。
2. **证据覆盖核验与补测清单**：逐项核验报告范围，输出补测、沿用、更新结论和证据页，并实时回写第一条工作流。

开发节奏采用最小可行实现路径，时间可以灵活安排，不把两天活动或某个 deadline 当作产品硬约束。首版先支持一个品类、一个市场、三张表和一组可复现规则，再补充多语言、多角色、更多检测项目与真实机构数据。

## 五、简化规则声明与边界

- 结论可复现：相同输入、规则版本和数据表应得到同一结论。
- 证据可回溯：每条结论都能回到报告编号、页码、原文片段和命中规则。
- 不确定就升级：缺失文件、范围不明、规则未命中或机构意见冲突时标记“待人工核验”。
- 人工覆盖留痕：记录操作人、时间、理由和规则版本，不能静默改结果。
- 系统提供证据整理、补测建议和代价估算，不替代检测机构、认证机构、监管部门或企业合规负责人的最终判断。
