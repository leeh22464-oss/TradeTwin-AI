### 实际修补验证

- 必须提供规则和证据版本；缺失版本、未知覆盖状态、覆盖无页码证据、人工核验均不能进入数值报价。离线参考与已核验测试夹具分开，未用夹具冒充生产证据。
- 证据、费用和范围变化可使同一文本重算；本地参考实际读盘更新不再复用永久缓存。
- 选择覆盖区间内方案后，同轮显式功率/驱动优先；随后只改语言或交期措辞仍保留选定配置。
- 待核验会话中的金额及英/德/中文天、周、月、日期/周次承诺被校验拒绝；真实邮箱草稿 API 回归检查同一规则。没有会话的通用检查仍可用。
- 材料和市场变化保留原文并等待人工核验，不按默认欧盟/原材料偷偷报价；后续选择或措辞修改不能清除该状态。测试包括英文代词 `us` 与 US 国家缩写区分、采购同事在德国不等于把美国目标市场改回德国。
- 邮箱 mock 检查只读选择、`BODY.PEEK[]`、不调用 STORE、已读状态不变、稳定线程/去重、草稿回复链。SMTP 发送函数、路由和界面均移除。
- 扩展 VM 执行真实消息监听脚本，检查选区优先、近期入站消息、排除出站/隐藏/可编辑节点、可信编辑器、预览、身份变化、同步重试。回填固定到已经验证的 tab，并在内容写入前再核对会话，避免异步切换买家。
- Node 同步按选中配置、数量、版本和确定性补测金额校验；历史 run 重放不会回滚新案件，保存/审计/缓存事务失败会回滚。
- 离线重置使用新演示 generation，重新分析能同步 round1，保留原 Python 会话、Node 案件和审计；真实 IMAP 身份不变。
- 最终独立审查复现 Python 原材料值 `original` 与 Node 的 `original-material` 不一致。已统一规范值，保留原文引用；新增真实 HTTP smoke 验证首次“原材料/德国”及 PVC/US → 恢复材料 → 恢复德国市场的状态：完整恢复后两端均就绪，仅恢复一项仍待核验。控制器最终在隔离端口63926/63927复测通过，Node152、Python123均通过；历史快照不重写，重新确认即可生成正确的新轮次。

## 已明确的限制

- 本记录中的自动化与隔离浏览器检查未发起真实外部模型请求，也未使用真实检测机构数据、真实企业费率或生产排期；主服务已识别本地模型配置。演示/回退模式会在界面中标识，规则结果、费用、证据和交期不由模型改写。知识 UI 的 ship 结论不等于真实 web_search 已成功调用。
- 本轮没有声称完整 WCAG、生产鉴权、多租户、性能指标或真实模型可用性；应用仍是本机单用户原型。
- 本地知识检索采用词法匹配，不是向量语义搜索；Obsidian 只有显式配置授权目录才会只读导入。
- 扫描 PDF 无 OCR；空文本或失败解析必须人工补录/确认，不会自动成为合规证据。
- 初始规则为简化演示规则，98% 是原框架目标，不是本项目测得的召回率。
