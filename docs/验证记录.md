## 案件队列与浏览器实际检查

隔离 QA 数据在队列检查时为 16 案，分页实测 **10 + 6**；随后追加 smoke 案件与 UI 新建合成案，最终为 18 案。主项目端口 3001 的原有 3 案未被本轮隔离 QA 修改。队列检查明细保存在 `test-results/queue-browser.json`，该文件属于忽略的运行证据。

已实际操作并核对：

1. 默认进入案件队列；跨客户、案件、型号和买家原话的空格分词 AND 搜索有效。
2. “未推演 / 含人工核验 / 含补测 / 已有回复”可组合筛选；空状态清除可恢复全部案件。
3. 更新最新/最早、客户 A–Z、费用从低到高/从高到低排序有效；未知费用在费用升/降序中都留在末尾，真实 €0 仍可排序。
4. 每页 10/20、列显示以及舒适/紧凑密度确实改变列表呈现；桌面列显示仅在桌面表格可用。
5. ≤1024px 使用摘要列表而不是过窄表格；1440、1060、900、768、399、390 六个最终宽度均无页面横向溢出。最终 DOM 检查还确认 1060/900/768/399/390 的 `asideBelow=true`、`barInside=true`、每个子项 `childrenInside=true`，`scrollWidth` 等于视口宽度。
6. 详情返回会保留队列搜索/筛选；配置、证据、账单、报价方案锚点可跳转，`top:71px` 固定分段导航与 `top:112px` 账单摘要不重叠；≤1100px 摘要变为两列。
7. 详情配置、数量或单价变脏后，返回或切换案件会打开自定义放弃确认；刷新或新建案件提示先保存；对话、方案和报价动作才会自动保存。保存失败保留输入并停止后续动作。未保存弹层的 Escape、初始焦点和焦点循环已实测。
8. 自动保存成功后选择方案 A 的重算结果与返回队列的状态、费用和回复标记同步；失败路径不清空输入。
9. 证据抽屉可看到规则、报告编号、页码和原文，键盘打开/关闭、Escape 和焦点恢复已检查。
10. ≤860px 导航的 Menu/X、独立滚动、Escape 关闭、焦点循环、主内容 `inert` 和关闭后的焦点恢复已实测。

## 已明确的限制

- 本记录中的自动化与隔离浏览器检查未发起真实外部模型请求，也未使用真实检测机构数据、真实企业费率或生产排期；主服务已识别本地模型配置。演示/回退模式会在界面中标识，规则结果、费用、证据和交期不由模型改写。知识 UI 的 ship 结论不等于真实 web_search 已成功调用。
- 本轮没有声称完整 WCAG、生产鉴权、多租户、性能指标或真实模型可用性；应用仍是本机单用户原型。
- 本地知识检索采用词法匹配，不是向量语义搜索；Obsidian 只有显式配置授权目录才会只读导入。
- 扫描 PDF 无 OCR；空文本或失败解析必须人工补录/确认，不会自动成为合规证据。
- 初始规则为简化演示规则，98% 是原框架目标，不是本项目测得的召回率。

更多实现范围和实际检查项见[工作台 A 方案验收](工作台A方案验收.md)；知识工作区截图和 mock 检查只作为本轮集成证据。
