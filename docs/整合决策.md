# 本轮整合决策

本文件公开记录实现中采用的判断，方便两位协作者复查与调整。

| 决策 | 原因 | 若判断不适用，影响与调整 |
|---|---|---|
| 直接在已有 `integration` 专用分支继续 | 这是带 Git 远程的独立仓库；外层目录只保存设计和原始输入 | 代码提交在内层仓库，外层不会自动获得代码历史；协作应使用内层仓库 |
| 共享 pytest 的工作流二 fixture | 原测试文件间无法自动共享，导致五项集成测试不能建立环境 | 小范围测试结构变化，不改变业务行为 |
| 开发代理增加 `/sales` 与 `/static` | Python 工作台和绝对静态资源地址需要从统一入口加载 | 增加两项本机代理；独立调试可继续直接访问 Python |
| 数值报价要求证据已解决；参考模式保持待核验 | Node 合成种子有独立已确认范围，Python 参考包缺少独立 EMC/材料核验 | 离线参考不展示价格，需补齐核验证据或运行 Node；测试专用已验证夹具不能当生产证据 |
| 材料/市场变更先保留原文并转人工核验 | v1 接口只评估功率、IP、驱动，不能忠实计算更宽配置 | 当前范围外场景需人工确认；后续可扩展版本化契约，不能静默套用默认值 |
| 方案字母以工作流一当前结果为准 | A 是原要求，是否有新驱动候选会影响覆盖区间方案是 B 还是 C | 旧主线固定 A/B 演示需按配置或 kind 识别，不能直接迁移字母 |
| 各轮存档不被历史重放覆盖 | 同一询盘的旧 run 可能因重试再次同步 | 重放返回当前案件；未知的旧轮次冲突需重新计算，不能允许回滚 |
| 离线重置使用新 generation，保留历史 | 清除 Python 会话却沿用旧 Node 案件会产生轮次冲突 | 重置增加新的示例案件；旧历史保留，可在未来显式归档 |
| 同步未完成时暂停打开品质与刷新 | 浏览器复现了打开旧轮次的竞态 | 请求期间短暂不可点击；失败时使用同一结果重试同步 |
| Vite 不监听 Python 环境和运行目录 | Windows 临时 junction 在并行测试时触发 EBUSY | 运行资料变化不触发前端热更新；源码仍正常热更新 |

保留 Node 与 Python 两个实现，避免跨语言重写双方工作流。Node 管证据、规则和共享案件；Python 管销售理解与表达。邮箱只写草稿、插件只填编辑器的边界来自用户明确要求。

本轮只进行本地开发、验证与 Git 整合，不推送、发布或发送外部消息。真实邮箱、登录后的国际站和模型凭据接入仍需单独验证；完整结果见 [验证记录](验证记录.md)。
