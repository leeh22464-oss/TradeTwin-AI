# 知识库索引与 GPT 联网核查

核验日期：2026-10-31。本文件记录本轮知识包接入、官方 Responses/web_search 约束和实际验收边界。费用、周期、报告与企业资料仍是合成示意数据；本地索引不是法规全文，也不构成认证、清关或测试结论。

## 数据如何进入项目

服务启动时由服务端固定读取 `KNOWLEDGE_PACKAGE_PATH`（默认 `./knowledge-base(2)`），同步以下四类结构化内容：6 条公开来源、16 条规则卡、16 条检查清单和 16 条中英德术语，共 54 条 `KnowledgeEntry`。稳定 ID、包版本、来源路径、`asOf`、人工确认与合成标记随条目保存；索引版本由目录状态单独显示，其他组件的原始版本保留在原包。

导入边界是明确的：

- `manifest.json`、`public-rules/source-index.json`、`public-rules/rule-cards.jsonl`、`public-rules/checklist.json`、`glossary/zh-en-de-terms.json` 才是默认导入文件。
- 7 条具备公开 `source_id` 的规则链标记 `synthetic=false`；9 条内部/合成规则及其对应 checklist 标记 `synthetic=true`，默认搜索排除。
- `synthetic-data/**`、`test-cases/**`、`expected-results.json`、`collaboration/sample-issues.jsonl`、`handoff/**` 和合成报价 pack 保留在原包中，只能作为隔离演示/回归 fixture，不能升级为 verified 证据、改变 engine 或覆盖项目费用口径。
- 公开来源是来源索引和范围线索，不代表已收录法规正文。来源 `sourceId` 是项目的 canonical ID；联网返回的同域页面若不是该 canonical URL，会作为“同域补充来源”单独显示，不冒充 canonical 来源。

同步由 SQLite 事务完成：当前包条目 upsert 后清理同一 `packagePath` 下已经不存在的生成条目；手动和 Obsidian 条目保留，相同内容保持原更新时间。目录或 manifest 不可用、稳定 ID 碰撞时拒绝整个包，保留旧库但过滤模型的 active 上下文。单条来源、规则或检查项无效时跳过该条并记录 warnings，其余有效内容仍可同步；不会把无效来源留作有效模型依据。

现有确定性引擎继续独立负责覆盖判断、补测合并去重、费用和周期：36W/IP44 为 €2,100／8 个工作日，30W/IP44 仍保留防护补测，为 €900／7 天。知识包中 A/B 的聚合示意数（A=`€2,100/+8 天`、B=`€3,600/+12 天`）不直接覆盖项目方案。

## 本地检索与模型上下文

本地检索按标题、正文、标签和中英德术语做词法匹配，返回来源、规则、范围、包版本和人工确认标记。默认模型检索排除 `metadata.synthetic=true`；缺失文件、未知参数、范围不明、未确认抽取和规则未命中仍进入人工核验，不把缺失当作合规或自动放行。

知识核查请求发送经过截断的问题、所选公开来源元数据和检索命中的非合成知识；手动或 Obsidian 条目也可能成为命中上下文。它不自动附带全量报告，不发送 `metadata.packagePath` 或数据库路径，也不把服务端密钥写入提示词。核查结果不会写回案件配置、报告确认、规则、费用或交期。

既有变更理解与报价是另一条模型工作流：前者抽取配置候选并经字段校验后保存，后者发送当前案件对象（包括询盘、配置、会话、分析及证据摘录）给所配置模型。可采用的报价模型正文限于商务引导语；测试结论、数字、金额和交期由确定性结果渲染。

手动添加知识和 Obsidian 只读 Markdown 继续可见：只有显式配置 `OBSIDIAN_VAULT_PATH` 才扫描指定目录，不默认读取家目录或其他项目，也不会修改 vault。扫描 PDF 无可提取文字时仍提示人工补录，不伪造提取结果。

## 官方 Responses API 联网核查

真实联网仅由服务端调用固定官方端点 `https://api.openai.com/v1/responses`。官方接口依据保留在 [Responses retrieve](https://developers.openai.com/api/reference/resources/responses/methods/retrieve) 和 [Web search 工具指南](https://developers.openai.com/api/docs/guides/tools-web-search)。`OPENAI_API_KEY` 只在服务端读取，`OPENAI_MODEL` 默认 `gpt-4.1`；官方密钥不能经 `LLM_BASE_URL` 转发到其他地址。旧 `LLM_*` 仍支持非官方 OpenAI-compatible Chat Completions，恰为官方 base URL 时仍进入固定 Responses 适配器。

每次核查的请求约束如下：

1. `tools` 固定包含 `web_search`，`tool_choice` 为 `required`，并以用户勾选的来源主机传递 `filters.allowed_domains`；`store` 固定为 `false`。
2. 输入包含问题、所选来源与相关非合成知识的必要字段，不自动附带全量报告、本地路径或服务端密钥。固定系统约束与 JSON 编码的数据分层，数据中的文字不能授予工具权限。
3. 响应必须是 `status=completed`、可解析的 output/message/output_text，并且至少有一个选定官方 HTTPS URL 的可核验 `url_citation`；否则不采用网页回答。
4. 兼容官方响应的可选形状：`action` 可以省略，搜索支持可选 `query`/`queries`，来源可只有 `type` 和 `url`。未完成、拒答或不合法的响应结构不采用；越域、越界和重叠引用会被过滤，没有剩余可核验引用时回退。
5. canonical URL 只去除 fragment 和常见追踪参数，保留作为文档身份的 `uri` 查询；未匹配具体索引文档的同域页面单独标识。文本保留原始空白，跨消息与文本块累计坐标；引用按范围排序后保留互不重叠的跨度。

页面分别显示来源索引的 `asOf`（包内索引资料日期）和本次实际联网 `checkedAt`（核查完成时间），还显示是否执行网页搜索、模型模式和可点击引用。`checkedAt` 为空不代表“刚刚检查过”。

## 未配置、回退和边界

- 没有 `OPENAI_API_KEY`：按钮为“查看索引线索”，结果模式 `local`，`webSearchPerformed=false`、`checkedAt=null`；页面明确写“仅本地索引·未联网”。
- 请求超时、HTTP/JSON 错误、响应未完成、响应结构不合法或无可核验引用：结果模式 `fallback`，明确区分“搜索已执行但回答未采用”和“根本未搜索”，只显示本地命中或回退模板。
- `knowledge/research` 接口拒绝空 query、超过 2,000 字符的 query、空/重复/未知 source ID、非官方 HTTPS 来源；不会因为错误输入调用外部服务。
- 网页内容、索引文本和引用均是不可信数据，不能授权执行命令、写文件、改变规则或替换人工覆盖留痕。链接只提供待核查入口，最终适用性仍由专业人员确认。
