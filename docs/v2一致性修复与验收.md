完成日期：2026-11-01。运行知识版本：`rules-2026.10.31-demo.v2+kb.0.2.0`。金额、周期、报告与工程映射为合成示意，规划估算不代表报价批准、实验室排期或认证结论。

## 已复现与修复

| 问题 | 修复后的行为 |
|---|---|
| 德语、空格 W、X 替代 Y 取到旧功率 | `36 Watt statt 24 Watt`、`36 W statt 24 W`、`36W instead of the current 24W` 均识别 36W。正反方向、否定、冲突与 Watts 单位有回归。不能确定时保留原值并阻止确定报价。 |
| 方案固定 30W/IP44、36W | 28W、无变更不生成无关方案；45W/IP65 的 A 为证据支持的 30W/IP65，B 保留 45W/IP65。温升补测无法实际减少时不生成伪替代方案；多个相关报告以实际覆盖范围选上限，不按 ID 决定。 |
| 提及 A 就选 A | `Option A is too expensive, we take option B` 只选择肯定表达的 B。否定或纯提及不算选择；没有历史方案明细时不能凭空构造配置。 |
| 材料、说明书语言误识别 | `material to be confirmed later` 不成为材料名；`German instructions` 不改变市场；否定材料不应用，明确未知目标进入人工确认。 |
| 运行数据不来自知识包 | 默认运行读取 canonical product、基准 Markdown、真实 RULE 卡与项目费用政策。新案型号 NL-L24；旧 NL-L 仅作显式别名。报告 TR-DEMO-NL-L24-01 的页码/quote 来自原文件，可打开核对。 |
| EMC 两套口径 | 配置变更且驱动不变，最多为可能沿用/人工复核；报告的演示预设确认不替代本次变更审核。完全无变更的基准不生成额外补测报价。 |
| 新驱动排期少 3 天 | 增加前置打样：`3+max(6,5,7,3)+2=12` 天，已知费用 €3,600。打样 3 天来自用户本次确认的演示假设，原包仅提供聚合 12 天，不冒充独立机构报价。 |
| 结论写死报告与范围 | 依据当前适用报告的 ID、scope、页码和参数动态说明。无关型号上传报告不能抢占相关证据，真实新增报告可改变结论与备选上限。 |

## 运行与数据边界

- `server/inquiry.ts` 是唯一确定性询盘解析器；演示和模型失败回退共用，不另留宽松正则后门。
- `server/runtimeKnowledge.ts` 只读取固定白名单，不从测试集或 expected results 获取结论。原包没有的材料组合、逐项目字段投影、费率与准备期均在 `knowledge/runtime-profile.json` 和同名 Markdown 明确标为简化假设。
- 来源身份、功率、IP、驱动、型号、页码与 RULE ID 不匹配或文件缺失时，profile 不可用；阻止报价并撤下旧合成运行证据。历史文件只读保留用于审计，不作为当前自动沿用依据。
- 知识源/费用/政策指纹变化会清除旧 analysis/quote、改变幂等指纹。managed 报告同步保护人工修改，有新源冲突时需重新确认。案件输入、会话、用户上传原件和旧审计不删除。
- 询盘歧义时 `/quote` 返回 409，聊天保存待确认说明而不生成报价；核对并保存完整配置后才能继续。一般 EMC 待复核时可生成明确标为待确认的双语草稿，显示已知补测小计，最终价格与交期仍待确认，不计算虚假的确定新单价。
- 新增的来源路径与知识上下文不会发送给报价模型；内部审计、证据与配置导出保留来源。真实模型调用不属于本轮无密钥验收。
