## 1、题目背景

外贸商家获取单个买家的成本可达数百元，但普遍面临三道坎：询盘转化低（缺乏买家背调与高效跟进）、重复人力成本高（上品、出图、客服等大量重复劳作）、跨岗位协同难（运营/业务/采购/美工/合规数据割裂，且商家 AI 使用能力弱，工具必须简单易用）。本题鼓励参赛队用 AI 打通"数据 → 知识 → 多角色工作流"，做出外贸人真能用、愿用的智能应用。

评审重点：场景是否真实贴合外贸业务、数据与知识库是否有效、产出是否本地化且可执行、以及应用与数据源连接是否稳定。

---

## 2、参赛任务

1. 确定核心业务场景（自选）：说明目标用户、目标平台或市场、核心业务问题与价值。说明触发方式、处理逻辑、输出形式及涉及岗位。
2. 创建 AI 应用 / 智能体（平台不限）：完成角色、任务、交互方式、目标平台/市场知识与必要能力配置。
3. 完成业务产出生成：支持中文（或目标语言）输入，生成面向至少 2 种目标语言、或至少 2 类角色/场景的本地化业务产出（话术 / 报价单 / 诊断报告 / Listing / 商品图等），体现商务语境与文化适配而非机器直译；鼓励实现批量生成（批量出图、批量上品）；完成至少两轮对话式迭代。
4. 完成本地化与业务适配：产出针对目标平台风格（阿里国际站 RFQ 回复 vs Amazon Listing vs TikTok 种草）做适配，符合平台规则。
5. 完成合规 / 规则校验与反馈：至少覆盖两类校验（目标国合规 / 平台规则 / 文化敏感 / 合同条款），至少两种反馈方式（文本批注 / 风险标记 / 可视化对比 / 语音）。
6. 完成现场演示：演示一段稳定、可重复的互动，展示至少两个相关工作流；建议体现数据与知识库调用，以及（可选）多岗位输出。

---

## 3、软件平台与现场支持

1. 平台不限：参赛队自选开发平台与工具链，现场可演示完整闭环即可。
2. 组织者提供参考资源（非强制）：

- 阿里国际站商家端帮助中心公开文档（平台规则、合规要求等）
- 合规与敏感词知识库（目标国认证、平台禁限售、广告法、文化禁忌）
- 可选的统一大模型 / 翻译 / 素材生成 API 额度  
3. 其余数据自取：其他平台相关数据多为付费资产，参赛队可自行获取，须确保合规授权、不违规爬取。  
4. 现场支持：技术人员答疑、可选外贸业务顾问、可选最小可运行示例脚手架。

---

## 4、评分标准与验收要求

基础要求（评分前提）

1. 支持中文/目标语言输入，生成面向至少 2 种目标语言或 2 类角色/场景的本地化业务产出，完成至少两轮对话式迭代。
2. 产出针对目标平台/市场做本地化与业务适配（非直译），覆盖至少 2 个目标平台或场景。
3. 至少覆盖两类校验（合规 / 平台规则 / 文化敏感 / 合同条款），并使用至少两种反馈方式。
4. 创建 AI 应用/智能体，完成角色、任务、交互方式及至少一项工作流、场景、知识库（可基于公开文档/商家数据自建）等能力配置，并完成一次实际调用。
5. 现场完成一段可重复的"理解→生成→校验→反馈"端到端互动，并展示至少两个相关工作流。
6. 能够说明用户输入、业务/市场数据、模型生成结果、合规校验结果在用户与应用之间的传递、调用关系、返回结果及异常处理方式。

## 5、交付物

1. **可运行作品：**可编译运行的完整工程包 + README + 平台配置导出 + 第三方组件声明，Tag 标记 `hackathon-final`。
2. **源代码：**可编译运行的完整工程包 + README + 平台配置导出 + 第三方组件声明，Tag 标记 `hackathon-final`
3. **项目海报：**尺寸0.8\*1.8m，用于游园会直观、可视化展示项目的内容
4. **3 分钟路演或现场演示**：PPT、HTML文件等可展示文件，用于项目最终路演环节；说明目标用户、核心场景、两个工作流、技术方案、平台配置、能力调用方式和现场效果。
