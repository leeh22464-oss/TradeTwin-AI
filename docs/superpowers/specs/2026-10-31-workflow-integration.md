# 双工作流整合设计

用户已要求使用 add-workflow-1 的业务流程替代主线重复部分，并保留主线证据核验。

- 工作流一保留 Python 编排、原文抽取、变更单、邮件/手动输入、英德回复与风险校验；通过同源 `/sales/` 工作台展示。
- 工作流二保留 Node 确定性引擎、SQLite、证据导入/确认、知识库与审计。新增 `tradetwin.wf2.v1` HTTP 适配层，所有代价来自运行库，不读取工作流一的补测表。
- React 案件详情聚焦品质核验，替换重复的销售对话、方案和报价区，提供销售工作台入口。
- Node 同源代理 `/sales/*`、`/api/workflow1/*`。工作流一返回后，按 session_id 同步案件、当前配置、轮次和回复到 Node；品质页可打开同一案件。质检证据改变后，工作流一须重新调用，不能命中旧快照缓存。
- 方案编号以工作流一为准：A 买家原要求，B 可选新驱动，后续字母为覆盖区间内功率替代方案。不得混用主线旧 A/B 含义。
- 明确欧盟德国室内固定式 LED 合成场景、材料沿用假设、估算费用、未知排期。缺失/无效证据停止确定报价，保留追问。
- 采用两进程兼容集成以保留双方现有实现，不重写跨语言引擎。根启动脚本负责生命周期；Python 依赖单独安装。

验收：两轮变更、方案选择后显式修改优先、证据变化重算、错误回退不报价、真实 HTTP 调用并同步案件；Node/Python 测试和构建。

## 输入与回复边界

- 邮箱通过只读 IMAP + BODY.PEEK[] 拉取，不改变已读状态；回复链优先，参与人/主题辅助，稳定身份保留跨轮上下文。回复写入带 In-Reply-To/References 的邮箱草稿，用户在邮箱自己发送；移除 SMTP 发送。
- 国际站插件优先选区，否则保守识别最近可见买家消息；先预览再分析。只向已验证的买家会话编辑器填草稿，无 click/submit/键盘发送行为；未知页面使用选区、粘贴或复制。
- 不支持的材料、市场等变更保留原文并进入人工确认，不按默认条件继续数值报价。
- 保存各轮完整结果与版本；历史 run_id 重放不能覆盖新轮次。品质侧改配置或证据后，报价就绪状态失效，等待确认应用与重算。

运行架构、接口、演示及当前限制见 [双工作流联调](../../工作流联调.md)。
